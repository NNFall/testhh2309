# Витрина цитатника

Решение тестового задания из [TASK.md](TASK.md). Служба написана на Python, работает на порту `8000`, хранит состояние в памяти и не требует внешней базы данных. Адрес каталога получает после запуска через `POST /catalog/source`.

## Запуск

```bash
docker build -t quote-showcase .
docker run --rm -p 8000:8000 quote-showcase
```

Для проверки в условиях задания:

```bash
docker run --rm --memory=256m --memory-swap=256m --cpus=0.5 --pids-limit=64 --tmpfs /tmp:rw,size=64m,noexec -p 8000:8000 quote-showcase
```

Проверка запуска:

```bash
curl http://localhost:8000/health
```

Ответ `{"status":"healthy"}` доступен до настройки каталога и приема снимка.

## API

| Метод и путь | Назначение |
| --- | --- |
| `GET /health` | Проверка жизни процесса |
| `POST /catalog/source` | Установка адреса каталога, например `{"url":"http://catalog:9000"}` |
| `POST /import` | Атомарная замена полного снимка |
| `PUT /catalog/{id}` | Локальная публикация или замена цитаты |
| `DELETE /catalog/{id}` | Снятие цитаты до следующего снимка |
| `GET /quotes/{id}` | Чтение полной записи; у `200` есть `X-Source` |
| `GET /stats` | Счетчики и размер данных в памяти |

Пример импорта:

```bash
curl -X POST http://localhost:8000/import -H 'Content-Type: application/json' --data-binary $'{"quotes":[\n{"id":"q-1","author":"Автор","text":"Цитата"}\n]}'
curl -i http://localhost:8000/quotes/q-1
```

## Как устроено решение

- `packed_store.py` разбирает снимок потоком и хранит цитаты в сжатых блоках с компактным индексом по `id`. Чтение возвращает все поля исходной записи.
- Новый снимок собирается отдельно. При ошибке разбора действующий снимок остается доступным; после успешной проверки происходит замена поколения. Правки, сделанные через витрину во время импорта, сохраняются.
- `PUT` и ответы каталога обновляют небольшой слой поверх снимка. Запись от `PUT` считается авторитетной и не перечитывается из каталога до следующего полного снимка. `DELETE` скрывает запись до следующего снимка.
- Читателю сначала отдается свежая локальная запись. После 15 секунд запускается фоновое обновление; после 55 секунд запрос ждет каталог с ограничением времени. Старее 60 секунд локальная запись не выдается.
- Одновременные запросы одного `id` объединяются. Исходящих обращений к каталогу не более четырех одновременно. После `503` соблюдается `Retry-After`; после тайм-аутов частота запросов снижается. Ответ `404` для отсутствующего `id` не кэшируется.
- Если каталог недоступен и локальная запись старше 60 секунд, витрина отвечает `503`. Иначе одновременно соблюсти предел возраста данных и отдать достоверный `200` невозможно.

## Проверки

Локально, без Docker:

```bash
python -m pip install -r requirements.txt pytest pytest-asyncio
python -m pytest -q
python showcase.py
```

Проверка двух больших снимков на уже запущенной службе:

```bash
python benchmarks/stress_import.py --count 340000 --random-bytes 180 --repeats 2
```

GitHub Actions запускает тесты, собирает Docker-образ и выполняет эту проверку, а затем ещё пять полных импортов с длинными случайными идентификаторами при лимитах из задания. Исходное задание сохранено в `TASK.md`.
