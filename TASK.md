# Витрина цитатника

## Контекст

«Цитатник» — сервис, где люди читают цитаты известных людей и делятся ссылками
на них. Сами цитаты живут в каталоге: там работает редакция, там же сводятся
права на публикацию. Каталог обслуживает всю компанию, читателей к нему не
пускают — между ними стоит витрина.

Витрина держит у себя содержимое каталога и отдаёт цитаты читателям по одной.
Содержимое приезжает двумя путями:

- раз в несколько минут каталог присылает витрине **полный снимок** одним
  запросом. Витрину при этом не перезапускают;
- между снимками редакция правит цитаты в каталоге, и витрина может прочитать
  из каталога **одну цитату** — по её идентификатору.

Вам нужно написать эту витрину.

## Использование нейросетей — разрешено

Пользуйтесь любыми инструментами, включая нейросети. Мы смотрим не на то, как
написан код, а на то, как служба ведёт себя в работе.

## Что мы обещали читателям и редакции

Это нижняя граница приемлемого, а не цель:

- читатель не ждёт ответа дольше **3 секунд**;
- правка, сделанная редакцией в каталоге, доезжает до читателя не дольше чем
  за **60 секунд**.

Мы смотрим не только на то, выполнены ли эти два обещания, но и на то,
насколько лучше них витрина работает.

## Технические рамки

- `Dockerfile` в корне репозитория; образ собирается и запускается без
  дополнительных действий.
- Служба слушает порт `8000`.
- Всё состояние — в памяти процесса. Внешние базы данных, кэши и брокеры
  запрещены; интернета у контейнера нет.
- `GET /health` обязан отвечать `200` сразу после старта и всё время работы.
- Язык — Python. Версия и набор библиотек — на ваш выбор.

## Каталог

Каталог — чужая система. Её адрес витрина узнаёт не из настроек: после старта
ей сообщают его запросом `POST /catalog/source` (см. ниже). До этого момента
витрина уже обязана отвечать на `/health`.

Интеграция с каталогом описана его командой так:

### `GET {адрес каталога}/quote/{quote_id}`

```json
200 {"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}
404 {"detail": "not found"}
503 {"detail": "busy"}
```

- `200` — актуальная запись каталога. Набор полей — тот же, что в снимке;
  обязательные поля `id`, `author`, `text`, остальные могут присутствовать.
- `404` — такой цитаты в каталоге нет.
- `503` — каталог сейчас не обслуживает этот запрос. В этом ответе есть
  заголовок `Retry-After` — сколько секунд подождать, прежде чем повторять.

Других кодов каталог не возвращает. Гарантий по времени ответа его команда не
даёт.

Отдельно нас просили передать две вещи.

Первая: каталог бывает недоступен целиком — не отвечает отказом, а не
отвечает вовсе. В такие минуты его поднимают, и поднимается он тем дольше, чем
плотнее в него стучат. Дважды его так и не подняли с первого раза именно
поэтому.

Вторая: каталог обслуживает всю компанию. Место в нём, занятое витриной, —
это место, которого не досталось другим его клиентам.

## Контракт витрины

### `GET /health`

```json
200 {"status": "healthy"}
```

Отвечает сразу после старта процесса и всё время работы.

### `POST /catalog/source`

```json
{"url": "http://catalog.internal:9000"}
```

```json
200 {"source": "http://catalog.internal:9000"}
```

Адрес может быть сообщён повторно — тогда действует последний.

### `POST /import`

Приём снимка каталога. Тело — JSON:

```json
{"quotes": [
{"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}
]}
```

Формат тела гарантирован: `{"quotes":[` на первой строке, затем **по одной
записи в строке**, записи разделены запятой в конце строки, `]}` на последней.
Гарантия касается только разбивки на строки — за содержимое самих записей
каталог не ручается.

Обязательные поля записи — `id`, `author`, `text`; остальные могут
присутствовать.

Снимок — **полное состояние каталога на момент съёмки**: цитаты, которой в
снимке нет, в каталоге на тот момент не было.

```json
200 {"imported": 340000, "dropped": 120}
```

`imported` — сколько записей пришло в снимке, `dropped` — сколько цитат
покинуло каталог.

Некорректное тело — `400`.

### `PUT /catalog/{quote_id}`

Редакция добавляет или заменяет одну цитату **через витрину**.

```json
{"author": "Марк Аврелий", "text": "…"}
```

- `author` — от 1 до 200 знаков;
- `text` — от 1 до 16384 знаков.

```json
200 {"id": "q-0000001", "author": "Марк Аврелий", "text": "…"}
```

Нарушение границ — `422`. Такая запись актуальна по определению: читателю она
отдаётся сразу после ответа и перечитывать её из каталога не нужно.

### `DELETE /catalog/{quote_id}`

Редакция снимает цитату с публикации через витрину.

```json
200 {"deleted": true}
404 {"detail": "not found"}
```

Снятая цитата читателям не отдаётся, даже если в каталоге она ещё есть, — до
следующего снимка.

### `GET /quotes/{quote_id}`

Чтение цитаты читателем. Ответ содержит запись **целиком** — все поля, которые
были у неё в снимке или в ответе каталога.

```json
200 {"id": "q-0000001", "author": "Марк Аврелий", "text": "…", "tags": ["стоицизм"], "year": 170, "lang": "ru"}
404 {"detail": "not found"}
```

Если цитаты нет ни у витрины, ни в каталоге — `404`. Что цитаты нет, витрина не
запоминает: редакция заводит их постоянно, и читатель, пришедший по свежей
ссылке, обязан увидеть цитату сразу.

Ответ `200` обязан содержать заголовок `X-Source`:

- `LOCAL` — отдано из того, что витрина держит у себя;
- `CATALOG` — за этим ответом витрина обращалась в каталог.

### `GET /stats`

Эксплуатационная сводка. Все величины — с момента старта процесса, только
растут (кроме `local`, `bytes` и `catalog`).

```json
200 {
"served_local": 10423,
"served_from_catalog": 512,
"catalog_reads": 96,
"evictions": 148,
"local": 63,
"bytes": 516159,
"catalog": 340000
}
```

| Поле | Значение |
|---|---|
| `served_local` | сколько ответов читателям витрина отдала, не обращаясь в каталог |
| `served_from_catalog` | сколько ответов читателям потребовали обращения в каталог |
| `catalog_reads` | сколько запросов витрина отправила в каталог |
| `evictions` | сколько записей витрина удалила у себя, не считая ушедших из снимка |
| `local` | сколько записей витрина держит наготове сейчас |
| `bytes` | сколько байт они занимают сейчас |
| `catalog` | сколько цитат витрина знает сейчас |

`served_from_catalog` и `catalog_reads` считаются независимо друг от друга и
совпадать не обязаны.

## Числовые рамки

| Параметр | Значение |
|---|---|
| Порт | `8000` |
| Память процесса | 256 МБ, без swap |
| CPU | 0.5 ядра |
| Процессы и потоки | не больше 64 |
| `/tmp` | 64 МБ, запуск файлов запрещён |
| Размер снимка | до 340 000 записей, до 110 МБ в одном запросе |
| Как часто приезжает снимок | раз в несколько минут |
| Длина текста цитаты | до 16 КБ |
| Ожидание читателя | не дольше 3 с |
| Возраст данных, отданных читателю | не больше 60 с |

## Как проверяется решение

- Контейнер поднимается **один раз на весь прогон**. Ручки сброса состояния
  нет, перезапуска между проверками нет.
- Сразу после старта витрине сообщают адрес каталога.
- Проверки изолированы друг от друга уникальными идентификаторами цитат.
- Счётчики `/stats` читаются до и после каждой проверки — важна разница, а не
  абсолютное значение.
- Проверяются коды ответов, тела, **заголовки** и **время ответа**, в том
  числе распределение задержек по серии запросов.
- Проверяется, что процесс жив и отвечает после каждого приёма снимка.
- Нагрузка подаётся из отдельного контейнера в той же сети; у него те же
  ресурсные лимиты, что у вашей службы. Там же живёт каталог.
